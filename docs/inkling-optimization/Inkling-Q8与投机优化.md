# 八位置 Q8 投影的实测收益

Inkling SQ-10、FP8 KV、单槽 16K、K=7、温度 0。补丁将具有第二输出行的 M=8 投影循环长度固定为 8，使编译器可展开循环，沿用原有 Q8 权重和 FP32 累加。

同进程中使用相同输入和八份轮换权重交替运行原版与候选各六组，每组 32 次真实 3072 × 2304 投影。按 GPU 时间计算，单次中位数从 0.211697 降至 0.067300 ms。另以原内核测试，一份权重重复读与八份轮换分别为 0.244298 和 0.234020 ms。这组数据约束了特定 Q8 投影的缓存假说。MoE 专家与硬件 DRAM 流量需要独立测量。

四批名录每轮 1,196 输出 tokens。依运行顺序，候选、基线、候选、基线的合计解码速度分别为 48.20、50.42、62.73、15.15 tok/s。对应验证图 GPU 时间中位数为 106.98、110.30、85.96、111.60 ms。第二轮基线出现提交后约 16.8 秒才开始执行的命令。候选的两轮输出均与完整贪心序列一致，P3 七题全部正确。候选三进程物理峰值最大 2,956,727,816 字节。稳定收益按同进程算子实测判断，服务吞吐仍受运行状态影响。

## 论文对选型的影响

- [LUT-GEMM](https://arxiv.org/abs/2206.09557) 将低比特编码与激活查表结合以减少反量化工作。移植到 SQ-10 要考虑专用编码、建表成本和每组实际使用的 token 数。
- [MoE-Infinity](https://arxiv.org/abs/2401.14361) 按稀疏激活轨迹预取与替换专家。统一内存上的可检验收益是减少慢尾期间的页迁入，而非笼统缓存所有投影。
- [REST](https://arxiv.org/abs/2311.08252) 使用匹配后缀的检索续文作为候选。仅用输入与已确认前缀的简化离线回放，7/15/31 上限分别需要 308/258/250 轮；三者均有 134 轮没有提议，现有 DFlash2 K=7 实测为 163 轮。
- [DLoop](https://arxiv.org/abs/2610.07659) 通过循环感知训练与置信门控，在一次验证前执行多段并行草稿。应用到本服务需要相应草稿权重及超过八位置的验证与回滚支持。
